# Guitar tuner iPhone app (accuracy first)

## Context

Daniel wants an iPhone app that tunes an electric guitar, modelled on the best existing tuners, with accuracy as the priority. Research (secondhand; no independent cents-level tests exist):

- Peterson iStroboSoft / StroboPro is the accuracy benchmark: claims 0.1 cent, strobe display, calibration to an external reference, sweetened tunings (paid add-on).
- GuitarTuna / Cleartune are the usability benchmarks: auto string detection, clean needle, reference tone, alternate tunings. Phone tuners in general land at roughly 2-5 cents.
- Technical limits that decide accuracy: FFT bins are too coarse at low E (82 Hz); iPhone mic rolls off below ~100-200 Hz so the fundamental is weak; YIN with parabolic interpolation is the standard fix (the Strobel app does this with vDSP).

So the app copies: Peterson's resolution, calibration and strobe-style display; GuitarTuna's auto string pick and reference tones. It does not copy: sweetened tunings (v1), ads, accounts.

## Design

**Capture.** `AVAudioSession` category `.record`, mode `.measurement` (turns off the automatic gain and voice processing that smear pitch). `AVAudioEngine` input tap at the hardware rate (48 kHz), ring buffer of 16384 samples. Shows the active input route so a USB/Lightning audio interface (cleaner electric signal) works with no extra code.

**Detection, two stages (pure Swift package `TunerCore`, no AVFoundation):**
1. Coarse pitch: YIN (difference function, cumulative mean normalization, threshold 0.1, parabolic interpolation), search range 60-400 Hz, via vDSP. Gives the note and rejects non-pitched noise.
2. Fine pitch: Hann-windowed 16384-sample buffer, evaluated with a direct DFT scan (no FFT setup) in about 0.25 Hz steps within +/-1.5% of the coarse estimate, then a parabolic fit on log magnitude (sub-0.01-bin error). Uses the fundamental whenever it is present. Only when the fundamental peak is under 25% of the strongest of harmonics 1-3 (phone mic roll-off) does it use harmonic 2 or 3 instead, corrected for string stiffness: f_n = n*f0*sqrt(1+B*n^2) with a nominal B of 1.5e-4.
   - Change from the first draft: averaging harmonics 1-4 would read up to 1-5 cents sharp on a real string, because higher harmonics of a stiff string run sharp. Guitarists tune the fundamental, so the fundamental wins and the harmonic path is a corrected fallback. B = 1.5e-4 is an assumption; the tests vary B from 1e-4 to 4e-4 to show the residual stays under 1 cent.
3. Stability: median of the last 5 readings, then light smoothing; hold the last good reading about 0.5 s after the pluck decays. Reported to 0.1 cent.

**Reference and calibration.** A4 adjustable 415-466 Hz (default 440). Equal temperament only.

**Tunings.** Standard, Drop D, half-step down, full-step down, DADGAD, open G, open D, open E. Auto mode picks the nearest string; tap a string to lock it.

**UI (SwiftUI).** Large note name, cents readout to 0.1, a strobe-style band (Canvas) that drifts left/right and freezes when in tune, plus a needle for quick reading. In tune = within 1 cent (green). Six string buttons that also play a reference sine (`AVAudioSourceNode`). Microphone permission string and a plain denied-state screen.

5. Install on Daniel's iPhone (device build needs `-destination "id=<UDID>"`, per the `ios-build` skill). Optional TestFlight via `app-ship`.

## How accuracy is proven (not assumed)

- Synthetic tests across all six standard strings (E2 to E4) at 44.1 and 48 kHz, detuned -50 to +50 cents. Pass bar: under 0.3 cent error on clean tones, under 1 cent with a weak or missing fundamental, 20 dB noise and a decaying harmonic-rich pluck model.
- A known-bad control: the same tests with the fine stage disabled must fail the bar, so a passing run means the detector works and is not a test that cannot fail. If YIN alone happens to pass the bar, report that instead of hiding it and tighten the bar or the signals until the control can fail.
- A known-good control: a pure sine at an exact frequency reads 0.0 +/- 0.1 cent.
- Real-world: play exact reference tones (generated on the Mac) into the phone mic and record the readout; compare with a second tuner if Daniel has one. Real guitar and mic response can only be confirmed on the phone by Daniel.

## Out of scope for v1

Sweetened tunings, chromatic mode for other instruments, polyphonic (strum) tuning, in-app purchases, accounts.
