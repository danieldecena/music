# Chords tab: follow-along chord flow, diagrams and tab (guitar tuner app)

(The earlier tuner build plan is in git history at 4da93cb; that work is done and installed.)

## Context

Daniel wants a second section in the private guitar tuner app (`~/developer/guitar-tuner`) that shows a song's chords as a flowing, auto-scrolling view like Apple Music's synced lyrics, so he can follow along while playing, with guitar tab for each chord. His answers:

- Follow mode: auto-scroll at the song's tempo, started by a Start button.
- Songs: imported from the Files app.
- Tab: a chord diagram plus a tab line for each chord.
- Lyrics: shown under the chords when a timed `.lrc` file is imported too.

What already exists, found in the music project:

- `Scripts/chords.py` writes `chords.txt` per song: header `# key Fm  110.3 BPM  81 bars`, then `bar<TAB>chord`, one chord per whole bar. Chord vocabulary is only major, minor, 7, maj7, m7; `-` marks a silent bar. Daniel's `02 DAISIES chords.txt` is exactly this.
- The bar grid is one fixed 4/4 tempo with bar 1 assumed at time 0. Detection is "unverified by ear" (author's own words), so charts are estimates.
- 57 timed `.lrc` lyric files exist (`[mm:ss.xx]text`).
- No guitar tab or chord-shape data exists anywhere. Chord shapes will be generated by rule in this app.
- Flip's Lyrics tab has no follow-along (static list), so nothing there to reuse. Flip's `.lrc` parser (`App/Flip/Analysis/TimedLyrics.swift`) is the pattern to mirror, not code to import.

## Design

All parsing, timing and chord-shape logic goes in the pure `TunerCore` package, tested with `swift test`. The app only draws it.

**TunerCore (new files, `TunerCore/Sources/TunerCore/`)**
- `ChordChart.swift`: parse `chords.txt`. Tolerates the stray character before `#` visible in Daniel's screenshot, blank lines, flats (Bb becomes A#), and `-`. Title from `# Chords -- NAME` (dropping `.m4a`), else from the file name.
- `SyncedLyrics.swift`: parse `.lrc` (multiple timestamps per line, ignore `[ar:]` style tags).
- `BarClock.swift`: bar length = 4 x 60 / BPM; bar index at time t with a user nudge offset, clamped; count-in of four beats before bar 1.
- `FlowLayout.swift`: turn chart plus optional lyrics into rows. With lyrics, one row per lyric line holding the bars that line spans (long lines wrap at 4 bars); without lyrics, 4 bars per row.
- `ChordShapes.swift`: chord name to six-string shape. A small table of open shapes (C A G E D F Am Em Dm E7 A7 D7 G7 C7 B7 Cmaj7 Amaj7 Dmaj7 Fmaj7 Gmaj7 Am7 Em7 Dm7), otherwise movable E-shape and A-shape barre shapes for the five qualities, lowest fret wins. Also renders the tab line text. Unknown qualities show the name with no diagram.

**App (`App/GuitarTuner/`)**
- `GuitarTunerApp.swift`: root becomes a `TabView` with two tabs, Tune (today's screen, unchanged) and Chords.
- `SongStore.swift`: imports via `.fileImporter` (multi-select; `.lrc` goes to lyrics, anything else to chords), uses security-scoped access, copies into Application Support so songs stay on the phone, lists and deletes the app's copies only.
- `ChordsTab.swift`: song list, import button, empty state saying how to import.
- `FollowModel.swift`: Start/Pause/Restart, four-beat visual count-in, nudge of 0.25 s earlier or later, tap any bar to jump there, screen kept awake while running.
- `FlowView.swift`: top card with the current chord's diagram and tab and a smaller "next chord" card; below it the flowing rows, current row large and bright, others dimmed, smooth auto-scroll, current bar highlighted.
- `ChordDiagramView.swift`: Canvas drawing of the six strings, dots, open and muted marks, barre bar, fret number.
- `TunerModel` / `AudioCapture`: stop listening when the Chords tab is shown and resume on Tune; deactivate the audio session on stop (with the "notify others" option) so music playing from another app resumes. Today it stays active.

## Honest limits to put on screen and in notes

- Chords are the Mac analyzer's estimate (one chord per whole bar, fixed tempo, bar 1 at time 0). A song with a long intro or tempo change will drift, hence the nudge and tap-to-jump.
- Diagrams are the standard shape for the chord name, not the record's voicing. This is not full song tab (no riffs or solos).
- Lyrics line up by the same fixed grid and inherit its drift.

## Verification

1. `swift test` in `TunerCore`: parser reads Daniel's real sample text (including the stray `r#`) and the repo's `Stems/htdemucs_6s/02 Let Em' Know/chords.txt` read-only; `.lrc` parser; clock boundaries; flow rows with and without lyrics.
2. Chord shapes, checked by music theory, not eyeballing: for all 12 roots x 5 qualities, derive the sounded notes from the frets on standard tuning and assert they contain the root, the right third and (for sevenths) the right seventh, and only chord tones. A deliberately wrong shape (a C major shape for C minor) must fail the same check, so the test can be shown to fire.
3. Build for simulator, then `scripts/install_iphone.sh`; the script confirms the app is listed and running.

## Out of scope

Listening to the song to follow chords live, playing the song inside the app, auto-sync of songs from the Mac, full riff or solo tabs, capo, other tunings for diagrams (standard only).
